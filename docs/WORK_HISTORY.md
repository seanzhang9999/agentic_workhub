# Agentic Workhub：本会话工作交付索引

这是软件、设计和脱敏验证记录，不是完整聊天逐字稿，不包含用户的专利、财务、旅行或随笔正文。真实会话ID、文档标识、登录材料和运行数据库保留在原机器，不进入公开仓库。

## 产品主线

利用各个 Agent 平台的原生能力，让用户工作在不同会话之间继续；把工作成果、目标、来源和关系留在平台之外。不是只做导出备份，也不把会话摘要冒充完整历史。

## 已交付模块

1. **范围锁定的飞书 MCP Gateway**：用户身份 CLI，命名根页面白名单，实时子树检查，版本冲突与幂等回执；支持读写普通文档、创建子页/随笔、上传图片及回执查询。
2. **Oracle/Docker 原始部署路径**：Dockerfile、Compose、初始化与 doctor 脚本。后续实际运行转至 Mac，未强制公开 MCP 端口。
3. **Mac CLI/LaunchAgent 运行路径**：真实 CLI/Node 路径与授权目录要分别配置；不把 npm 常见路径当作已验证事实。Tunnel 独立管理。
4. **本地 Web Viewer**：独立 8788 loopback 服务、飞书官方 Docs Component、独立 OAuth/PKCE、服务端签名；不导出 CLI token，不代理 Cookie。
5. **双链接与讨论交互**：原飞书链接与本地链接；复制选文后手动粘贴、补充问题、预览指示、下载讨论包；不假称自动读取跨域选区。
6. **文档空间**：授权根目录、数量、文档背景/目标/来源、关联会话。
7. **会话控制区**：register_context/read_context/list_contexts；最小自述、原生身份线索、来源证据、业务时间与采集时间分离；三类登记提示词。
8. **固定协调端采集器**：用户输入会话ID/引用，程序保存队列，固定 Codex 会话核对与发问，等待同步、关联回复、代登记。尚无网页自动唤起协调会话或后台无人值守适配器。

## 跨会话验证与发现研究

- 实测了已知 ID 的 ChatGPT 原聊天读取、向同一原会话发送仅自述请求、回读并代登记；也实测本地 Codex 任务自述。没有把发送回执等同完成。
- 用户提供“添加到 Codex”的原生引用后，可读取一个之前未出现在最近列表中的老聊天；更新活动后该聊天出现在列表并带项目关联。
- 当时桌面工具 list_threads 最多50条非置顶记录，无游标/项目过滤；不代表平台永久没有全量枚举能力。
- 本机 App Server 分页获得更多交互式 Codex 记录。主会话目录排除子Agent和无用户事件的执行记录；本地cwd不能当成ChatGPT项目ID，无项目也不能由缺失映射强行推定。
- 社区的非官方后端导出器有普通列表分页和项目内列表路径，但需要账号登录材料；本轮没有安装、运行或提取凭据。
- 一次回复在界面可见但采集端尚未读到，之后刷新成功。因此采集器有 awaiting_sync，禁止因为 idle 就判定未回复或自动重发。

## 非浏览器路线与后续演进

发现源提供定位线索，不直接驱动任务。先核对权限与真实会话，再生成唯一请求。平台适配层未来可接入原生完整分页、显式导入索引、用户选择的浏览器扩展，但不得自动读取凭据或扩大采集范围。
先支持单个固定协调端，再实现经验证的唤起接口；结果/建议与写入授权分离。用户拥有工作结构，Agent附着其上，而不是把所有结构封装在一个平台的聊天上下文里。
