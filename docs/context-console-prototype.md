# AWiki：文档空间与会话控制区

## 产品主张

文档是成果，会话是来历，任务是一次执行。三者有关联，但不是同一个对象。
用户先选择“围绕什么成果、沿着哪段上下文、交给谁”，再决定是否启动 Agent。
我们要保留的是可以重新进入工作的入口，而不是把另一个聊天框塞在文档旁边。

## 2026-09-05 已实现

- `/space` 展示现有授权根及子文档，统计本次发现页面，保留层级。数量包含根页面；不足/截断不能称为全量。
- Docx 进入本地原生组件；其他类型只提供原链接。
- 文档页右侧：引用快照、问题、讨论方式、完整指示预览；复制或下载 Markdown 讨论包。未实现选区自动捕获。
- 文档背景：来源线索、简介、目标，明确“未记录”；用户点击保存才写入本机独立文件，不改飞书原文。
- 会话控制区：平台、原生会话标识、来源依据、Agent 标签、目标、结论、未决问题、下一步、关联文档。所有记录标为登记快照，不能冒充实时任务状态。
- MCP 新增 `register_context`、`read_context`、`list_contexts`。原有 10 个工具保持，当前共 13 个。新增权限只涉及用户要求的本机登记区，不扩大飞书授权根。
- `/guide` 提供三套可复制提示词：写入后登记、旧文档补登、Agent 自述登记。真实文本维护在 `src/prompts.js`，以网页提供的版本为准。
- 登记原生会话 ID 不等于接通原会话，也不赋予运行权限。ChatGPT 普通 `/c/` 链接可以打开；其他平台不拼凑未经验证的深链。
- “演示下一步”是明确标注的本地状态模拟，不实际发消息、不启动 Agent、不改原文。

## 两种背景信息不要混淆

| 记录 | 谁维护 | 含义 |
| --- | --- | --- |
| 文档简介/目标/来源线索 | 用户在文档页手动保存 | 该文档的长期说明，可能尚未核验 |
| 会话登记卡 | Agent 经用户要求登记 | 某次工作上下文的最小摘要；文档可以关联多张卡 |

两者不互相覆盖。已有文档的来源未知是合法状态。补登会话不能被当作原创会话。
首版没有自动分析全部正文，也没有自动收集聊天历史或读取隐藏指令。

## 标识契约

- `context_id`：AWiki 登记键，稳定、可重复更新。它不是平台会话 ID。
- `provider + native_session_id`：平台定位线索。原生 ID 不可得时必须 `null`。在 Codex 中这里记录可续谈的 thread ID；不要与 App Server 的 session-tree ID 混淆。
- `session_url`：用户正常打开的原会话链接，不创建公开分享链接，不含授权参数。
- `identity_basis`：来自运行环境、用户提供、旧记录，还是无法核实；这是自述依据，不是身份认证。
- `document_refs`：当前允许根中的文档关联，不自动证明“创建了该文档”。
- `revision`：登记卡并发更新版本；写入原文仍使用原有文档版本规则。

未来批量导入需额外明确账户/工作空间、原项目 ID、原生 thread ID、采集时间、原始内容覆盖区间、失败原因和导入批次。不要仅按标题去重；同名不同会话不能合并。平台 ID 相同但账户不同也不能混合。

## 复制以外的路线：可行性分层

### A. 返回原会话（现在最小、最可靠）

保存真实会话链接，点击打开后由用户继续。解决“找回上下文”，不宣称自动注入问题。Codex 可由应用内导航工具打开指定任务，但这些工具没有被网页直接暴露。

### B. 用户控制的 Codex 适配器（建议下一步先做）

官方 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 提供 `thread/list`、`thread/read`、`thread/resume`、`turn/start`。
因此可以做“列出可见任务 → 选择真实 thread → 预览引用与问题 → 确认后续谈”。
必须先验证运行主机、账户和存储是否能看到目标线程；不能保证新启动的 App Server 自动拥有桌面应用的全部任务。对找不到的线程报告不可访问，不创建新线程假装续谈。
AWiki 网页只调用受保护的窄适配器，不能暴露通用 shell、任意 App Server RPC 或允许外站请求的本地端口。
当前 Codex 应用已提供列举/读取/打开/续发任务的内置工具；这些是当前应用能力，不是已安装的 AWiki 插件，也不是通用公网 API。本轮未用它们启动其他任务。

### C. 自己的 Agent Runner + 持久任务箱（长期主线）

把任务提交到用户控制的服务；Agent 离线时排队，接收后产生明确回执；运行结束把结果附着到文档与会话卡。
使用普通 HTTPS 提交和状态接口，SSE/WebSocket 仅用于更新状态，不作为唯一持久载体。
任务需要稳定 id、目标 Agent、上下文 id、引用快照、原文引用、执行边界、取消状态与显式确认；至少一次投递必须幂等。
结果与写入分开：先返回建议，用户明确要求写入后再走已有文档版本检查。
MCP 仍负责读取文档、登记上下文等工具调用，不承担“自动唤醒任意聊天”的职责。

### D. Responses / Conversations API 自有会话

[官方会话状态文档](https://developers.openai.com/api/docs/guides/conversation-state) 支持 API 自建长期会话。
可以完全控制会话生命周期，但它不证明能恢复消费者 ChatGPT 的现有聊天；两种 ID 不能混用。此路线需要单独的 API 账户配置、成本和运行治理，不在本轮暗中启用。

### E. 浏览器扩展或自动化

可作为用户明确点击后的“当前页面采集/定位/填入待发草稿”适配器候选；要逐项确认扩展权限、来源和实际兼容性。
不建议把依赖页面结构的自动发送作为主通道，不读取站点 Cookie、不调用未公开内部接口、不在后台扫描全部聊天。
当前环境未提供插件目录搜索接口，未发现一个已经可用且经过验证、能把 AWiki 网页请求直接续发至任意 ChatGPT 既有会话的插件。这不是断言市场上不存在。

## 快速导入：有项目与没有项目

[项目与聊天官方说明](https://learn.chatgpt.com/zh-Hans/docs/projects) 描述项目如何组织聊天、共享文件与上下文；它不承诺普通聊天有完整遍历项目所有逐字稿的 API。

1. **Codex 可见任务**：可以基于官方分页列表/读取能力做受控批量导入。先列表预览，仅对用户选中的记录读取内容与生成摘要。归档、不同来源类型、不可访问主机需要单独覆盖与报告。
2. **ChatGPT 项目**：如果当前客户端确实提供项目和聊天枚举接口，按返回的真实项目关联筛选；不能靠“在项目里说一句”假定所有会话可完整访问。没有接口时，使用用户提供的导出数据或明确授权的前台浏览器逐项采集，先展示范围。
3. **零散聊天**：原项目 ID 可空，进入“未归组会话”；用户按时间、标题、标签或关联文档筛选，确认后登记。无需先移动原平台聊天。
4. **单个会话自述**：在每个会话里用 `/guide` 的提示词登记，成本最低且不依赖全账户读取能力。可以将“任务完成后登记”加入用户明确配置的项目工作规范，但不保证从此自动回溯历史会话。

必须显示导入覆盖度：发现 N / 已选 N / 已读取 N / 摘要待确认 N / 失败 N；显示时间范围、截断和失败原因。
用户未选中的会话不进入控制区。导入摘要不自动导入完整附件或全文。导出文件缺少原 ID 时保留“来源未知”，允许后补，不编造。
本轮没有执行批量扫描或导入；仅登记当前已确认任务。

## 下一步原型故事

### 故事一：从文档找回“当时为什么这么想”

Sean 打开文档空间，看见项目根下的文档及其目标。点击某篇文章，右侧显示两张相关会话卡：“初稿推演”和“反例检查”。他选择后者，看见尚未解决的问题；点击返回原会话，继续原来的讨论。
如果只有摘要没有可恢复 ID，明确显示“以摘要承接”，不说“恢复了全部上下文”。

### 故事二：利用碎片时间交代工作

Sean 在手机读文档，引用一段“Agent 应附着在用户的信息结构上”，问“哪些机制可以替代对平台会话的依赖？”。
选择已配对的研究 Agent 与相关会话；预览文档范围和只读规则后提交。Agent 离线时显示排队，接收后显示回执；Sean 离开也不会丢任务。
Agent 返回结论与反例，结果挂在这篇文档旁。Sean 次日选择其中一条追问，或明确批准合并进正文。

### 故事三：整理多年零散聊天

Sean 选择“导入来源”，选一个项目或一组未归组会话。系统先列标题、时间和来源，不立刻全量上传。
他勾选 12 条，其中 10 条可读、1 条缺失、1 条未授权。系统呈现准确清单而不是“全部导入成功”。
摘要可关联已有文档，但不凭标题自动认定创作来源。用户确认后形成会话卡；原聊天不移动、不公开。

## 后续实施顺序与验收

1. **来源选择与导入清单**：先做 Codex 指定项目/工作目录可见记录，用户确认后只读导入；支持重复导入去重与失败重试。
2. **续谈适配器**：只支持一个已验证的本机 Codex 目标；点击一次生成一次 turn，重复提交不重复执行；目标不可见时不另建任务。
3. **独立任务箱**：再上服务器和手机入口。配对、密钥与运行权限单独设计，不把 context_id 当认证。
4. **结果附着**：输出与文档、任务、会话建立可追溯关系；写入前显示改动与目标版本。

先不做：全账户自动抓取、实时跨产品会话镜像、后台自动发消息、自动写回、任意主机控制、把复制按钮伪装成真实发送。
